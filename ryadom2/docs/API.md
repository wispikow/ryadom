# Документация API «Рядом»

Базовый адрес: `http://localhost:3000/api` (порт задаётся переменной `PORT`).
Формат обмена — JSON (`Content-Type: application/json`), кодировка UTF-8.

## Содержание

| Метод | URL | Доступ | Назначение |
|---|---|---|---|
| GET | `/api/health` | открытый | Проверка работоспособности |
| GET | `/api/tags` | открытый | Список тегов |
| GET | `/api/tracks` | открытый | Список треков (фильтр, поиск, сортировка, пагинация) |
| GET | `/api/tracks/:id` | открытый | Один трек |
| GET | `/api/videos` | открытый | Список видео |
| GET | `/api/tips` | открытый | Советы |
| GET | `/api/states` | открытый | Эмоциональные состояния |
| GET | `/api/quotes/random` | открытый | Случайная цитата |
| POST | `/api/requests` | открытый (с лимитом частоты) | Отправка обращения из формы |
| GET | `/api/requests` | администратор | Список обращений |
| PATCH | `/api/requests/:id` | администратор | Смена статуса обращения |
| DELETE | `/api/requests/:id` | администратор | Удаление обращения |

## Общие правила

### Формат ошибок

Любая ошибка возвращается в едином виде:

```json
{
  "error": {
    "code": "validation_error",
    "message": "Проверь заполнение полей",
    "details": { "email": "Введи корректный адрес почты" }
  }
}
```

Поле `details` присутствует только у ошибок валидации.

### Общие коды ошибок

| Статус | `code` | Когда |
|---|---|---|
| 400 | `bad_request` | Некорректный параметр запроса или `id` |
| 400 | `validation_error` | Тело запроса не прошло проверку (см. `details`) |
| 400 | `bad_json` | Тело запроса — невалидный JSON |
| 401 | `unauthorized` | Нет или неверный токен администратора |
| 404 | `not_found` | Ресурс или маршрут не найден |
| 413 | `too_large` | Тело запроса больше 20 КБ |
| 429 | `too_many_requests` | Превышен лимит отправки обращений |
| 500 | `internal_error` | Внутренняя ошибка сервера |
| 503 | `admin_disabled` | Админ-доступ не настроен (production без `ADMIN_TOKEN`) |

### Аутентификация администратора

Маршруты управления обращениями (`GET`, `PATCH`, `DELETE /api/requests…`) требуют заголовок:

```
Authorization: Bearer <ADMIN_TOKEN>
```

- Токен задаётся переменной окружения `ADMIN_TOKEN`.
- Если `NODE_ENV` не равен `production` и `ADMIN_TOKEN` не задан, используется токен для разработки `ryadom-admin`.
- В режиме `production` без `ADMIN_TOKEN` эти маршруты отвечают `503 admin_disabled`.
- Остальные маршруты авторизации не требуют.

### Ограничение частоты

`POST /api/requests` — не более 10 запросов за 10 минут с одного IP. При превышении — `429 too_many_requests`.

## GET /api/health

Проверка работоспособности сервера.

**Ответ `200`:**

```json
{ "status": "ok" }
```

## GET /api/tags

Список всех тегов (категорий), отсортированный по названию.

**Ответ `200`:**

```json
{
  "items": [
    { "id": 1, "name": "без негатива" },
    { "id": 7, "name": "вера в лучшее" }
  ]
}
```

## GET /api/tracks

Список музыкальных рекомендаций. Используется блоком «Время для музыки» и кнопкой «Больше треков».

**Query-параметры (все необязательные):**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `tag` | строка | — | Только треки с тегом с таким названием (точное совпадение) |
| `q` | строка | — | Поиск по названию или исполнителю (подстрока, до 100 символов) |
| `sort` | `order` \| `title` \| `artist` | `order` | `order` — порядок подборки, `title` — по названию, `artist` — по исполнителю |
| `limit` | целое 1–50 | `6` | Размер страницы |
| `offset` | целое 0–100000 | `0` | Сколько записей пропустить |

**Пример:** `GET /api/tracks?limit=1&offset=0`

**Ответ `200`:**

```json
{
  "items": [
    {
      "id": 1,
      "title": "Улыбайся",
      "artist": "IOWA",
      "cover": "/assets/img/cover-iowa.webp",
      "listenUrl": "https://music.yandex.ru/search?text=IOWA%20%D0%A3%D0%BB%D1%8B%D0%B1%D0%B0%D0%B9%D1%81%D1%8F",
      "featured": true,
      "tags": ["без негатива"]
    }
  ],
  "total": 12,
  "limit": 1,
  "offset": 0,
  "hasMore": true
}
```

`total` — количество треков, подходящих под фильтр; `hasMore` — есть ли следующая страница.

**Ошибки:** `400 bad_request` — недопустимые `sort`, `limit` или `offset`.

## GET /api/tracks/{id}

Один трек по идентификатору.

**Параметры пути:** `id` — номер трека.

**Ответ `200`:**

```json
{
  "id": 4,
  "title": "Stronger",
  "artist": "Kelly Clarkson",
  "cover": "/assets/img/cover-stronger.webp",
  "listenUrl": "https://music.yandex.ru/search?text=Kelly%20Clarkson%20Stronger",
  "featured": true,
  "tags": ["не сдаваться", "становиться сильнее после трудностей"]
}
```

**Ошибки:** `404 not_found` — трека с таким `id` нет.

## GET /api/videos

Видеоподборка.

**Query-параметры:**

| Параметр | Тип | Описание |
|---|---|---|
| `kind` | `podcast` \| `music` | Необязательный фильтр по типу видео |

**Ответ `200`:**

```json
{
  "items": [
    {
      "id": 2,
      "kind": "music",
      "title": "Плейлист треков на фон",
      "thumbnail": "/assets/img/video-music.webp",
      "duration": null,
      "watchUrl": "https://www.youtube.com/results?search_query=...",
      "featured": false,
      "tags": ["настроение", "отдых", "ностальгия"]
    }
  ]
}
```

`duration` — строка вида `"12:24"` или `null`.

**Ошибки:** `400 bad_request` — недопустимое значение `kind`.

## GET /api/quotes/random

Случайная цитата для кнопки «Мотивашка».

**Query-параметры:**

| Параметр | Тип | Описание |
|---|---|---|
| `exclude` | целое ≥ 0 | `id` цитаты, которую не нужно возвращать (чтобы не повторять текущую) |

**Ответ `200`:**

```json
{ "id": 2, "text": "Один шаг за раз — это тоже движение вперёд" }
```

**Ошибки:** `400 bad_request` — некорректный `exclude`; `404 not_found` — в базе нет цитат.

## POST /api/requests

Создание обращения из формы. Запись сохраняется в таблицу `requests` (SQLite) со статусом `new`.

**Тело запроса:**

| Поле | Тип | Обязательное | Правила |
|---|---|---|---|
| `fullName` | строка | да | 2–120 символов; только буквы, пробелы, `'`, `’`, `.`, `-`; лишние пробелы схлопываются |
| `email` | строка | да | формат `имя@домен.зона`, до 254 символов; сохраняется в нижнем регистре |
| `phone` | строка | да | после удаления пробелов, `(`, `)`, `-` — от 10 до 15 цифр, допустим ведущий `+`; сохраняется в очищенном виде |
| `socialUrl` | строка | да | корректный URL, до 300 символов; если нет `http://`/`https://`, подставляется `https://`; в имени хоста должна быть точка |
| `message` | строка | да | от 10 до 2000 символов |

Значения обрезаются по краям пробелов. Лишние поля игнорируются.

**Пример запроса:**

```json
{
  "fullName": "Иванов Иван",
  "email": "ivanov@gmail.com",
  "phone": "+7 (999) 123-45-67",
  "socialUrl": "t.me/ivan",
  "message": "Очень волнуюсь перед ЕГЭ, не могу спать"
}
```

**Успешный ответ `201`:**

```json
{
  "success": true,
  "id": 1,
  "message": "Спасибо! Мы получили твоё обращение."
}
```

**Ошибки:**

| Статус | Описание |
|---|---|
| 400 `validation_error` | Одно или несколько полей не прошли проверку. В `details` — сообщение для каждого поля |
| 400 `bad_json` | Невалидный JSON |
| 413 `too_large` | Тело больше 20 КБ |
| 429 `too_many_requests` | Больше 10 обращений за 10 минут с одного IP |

Пример ответа `400`:

```json
{
  "error": {
    "code": "validation_error",
    "message": "Проверь заполнение полей",
    "details": {
      "email": "Введи корректный адрес почты",
      "message": "Опиши подробнее — минимум 10 символов"
    }
  }
}
```

## GET /api/requests

Список обращений. **Требуется токен администратора.**

**Query-параметры:**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `status` | `new` \| `in_progress` \| `done` | — | Фильтр по статусу |
| `order` | `asc` \| `desc` | `desc` | Сортировка по дате создания (`asc` — старые первыми) |

**Пример запроса:**

```
GET /api/requests?status=new
Authorization: Bearer ryadom-admin
```

**Ответ `200`:**

```json
{
  "items": [
    {
      "id": 1,
      "fullName": "Иванов Иван",
      "email": "ivanov@gmail.com",
      "phone": "+79991234567",
      "socialUrl": "https://t.me/ivan",
      "message": "Очень волнуюсь перед ЕГЭ, не могу спать",
      "status": "new",
      "createdAt": "2026-10-21T13:11:21Z"
    }
  ]
}
```

**Ошибки:** `401 unauthorized` — нет или неверный токен; `400 bad_request` — недопустимый `status`; `503 admin_disabled`.

---

## PATCH /api/requests/{id}

Изменение статуса обращения. **Требуется токен администратора.**

**Параметры пути:** `id` — номер обращения (целое ≥ 1).

**Тело запроса:**

| Поле | Тип | Обязательное | Допустимые значения |
|---|---|---|---|
| `status` | строка | да | `new`, `in_progress`, `done` |

**Пример запроса:**

```json
{ "status": "done" }
```

**Ответ `200`** — обновлённое обращение (структура как в `GET /api/requests`):

```json
{
  "id": 1,
  "fullName": "Иванов Иван",
  "email": "ivanov@gmail.com",
  "phone": "+79991234567",
  "socialUrl": "https://t.me/ivan",
  "message": "Очень волнуюсь перед ЕГЭ, не могу спать",
  "status": "done",
  "createdAt": "2026-10-21T13:11:21Z"
}
```

**Ошибки:** `400 bad_request` — некорректный `id`; `400 validation_error` — недопустимый `status`; `401 unauthorized`; `404 not_found` — обращения нет.

---

## DELETE /api/requests/{id}

Удаление обращения. **Требуется токен администратора.**

**Параметры пути:** `id` — номер обращения (целое ≥ 1).

**Ответ `204`** — без тела.

**Ошибки:** `400 bad_request` — некорректный `id`; `401 unauthorized`; `404 not_found` — обращения нет.

---

## Примеры вызовов (curl)

```bash
# Отправить обращение
curl -X POST http://localhost:3000/api/requests \
  -H "Content-Type: application/json" \
  -d '{"fullName":"Иванов Иван","email":"ivanov@gmail.com","phone":"+79991234567","socialUrl":"t.me/ivan","message":"Очень волнуюсь перед ЕГЭ"}'

# Следующая страница треков
curl "http://localhost:3000/api/tracks?limit=6&offset=6"

# Просмотреть обращения (администратор)
curl -H "Authorization: Bearer ryadom-admin" http://localhost:3000/api/requests

# Отметить обращение обработанным
curl -X PATCH http://localhost:3000/api/requests/1 \
  -H "Authorization: Bearer ryadom-admin" -H "Content-Type: application/json" \
  -d '{"status":"done"}'
```
